# Параметры обслуживания Cinema Booking System

## 1. SLA / SLO / SLI

### SLA (Service Level Agreement) — Соглашение об уровне сервиса
**Целевая доступность:** 99.9% (три девятки)
**Допустимое время простоя в год:** 8.64 часа
**Допустимое время простоя в месяц:** 43.2 минуты

### SLO (Service Level Objective) — Целевой показатель
| Метрика | Целевое значение |
|---------|------------------|
| Доступность API | 99.9% |
| p95 latency POST /movies | < 500 мс |
| p95 latency GET /movies/{id} | < 100 мс |
| Error rate (5xx) | < 1% |

### SLI (Service Level Indicator) — Фактические метрики
- **Uptime:** процент успешных запросов за период
- **Latency:** время ответа сервиса (p50, p95, p99)
- **Error rate:** доля 5xx ответов от общего числа запросов

## 2. MTBF / MTTR

### MTBF (Mean Time Between Failures) — Среднее время между отказами
**Целевое значение:** 720 часов (30 дней)
**Расчёт:** При доступности 99.9% и MTTR = 1 час:
MTBF = (Uptime × MTTR) / (1 - Uptime) = (0.999 × 1) / 0.001 = 999 часов


### MTTR (Mean Time To Repair) — Среднее время восстановления
**Целевое значение:** 1 час
**Стратегия достижения:**
- Автоматический restart контейнеров через Docker (`restart: always`)
- Health checks для раннего обнаружения сбоев
- Резервные копии БД для быстрого восстановления данных

### CLI (Critical Level Indicator) — Критические индикаторы
| Компонент | Критический порог | Действие |
|-----------|-------------------|----------|
| PostgreSQL | CPU > 90% более 5 мин | Алерт + масштабирование |
| Redis | Память > 80% | Алерт + очистка кэша |
| RabbitMQ | Очередь > 10000 сообщений | Алерт + добавление consumer |
| booking-service | Error rate > 5% | Алерт + rollback |

## 3. Отказоустойчивость компонентов

### booking-service
- **Restart policy:** `always` (автоматический перезапуск при падении)
- **Health check:** HTTP GET /health каждые 30 секунд
- **Graceful shutdown:** корректное закрытие соединений при остановке

### PostgreSQL
- **Restart policy:** `always`
- **Volume:** данные сохраняются между перезапусками
- **Backup:** ежедневный полный бэкап + WAL архивирование

### Redis
- **Restart policy:** `always`
- **Данные:** кэш восстанавливаем, потеря не критична

### RabbitMQ
- **Restart policy:** `always`
- **Durable queues:** сообщения сохраняются при перезапуске
